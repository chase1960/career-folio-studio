# 中文求职工作台 · 开发 PRD v1.0

版本日期 2026-11-20　｜　使用对象：产品、设计、前端、后端、AI 工程与测试

用户用同一份真实经历材料，比较目标岗位，制作可投递的简历，并为选定的公司和岗位准备面试。首版交付四个工作台，重点验收两种连续性：同一条经历可以从原文追溯到简历和面试案例；手改过的简历可以继续交给 AI 局部修改，再按眼前的版本导出。

## 1. 产品边界与开发约定

| 已确认的产品要求 | 落到界面或行为 |
|---|---|
| 职业入口只露出三个大类 | **计算机、互联网、金融**。进入大类后再选具体岗位，岗位和 JD 共同决定取材、R 追问及面试侧重点。 |
| 服务两种当前任务 | “从经历开始做简历”提供完整引导；“用现有简历适配岗位”以原稿为底稿，优先调整少量措辞、证据顺序和篇幅。 |
| 四个工作台共用个人材料 | 个人经历台、岗位匹配分析台、简历优化台、面试打磨台。简历仓库属于优化台，可从工作台直接进入。 |
| R 必须检查，事实由材料或本人支持 | 优先量化，其次追问真实采用、交付或试点。主管认可须由本人明确确认。 |
| 手动和 AI 都能修改简历 | 在线画布提供 PPT 式编辑，AI 支持选区指令。所有修改作用于当前版本，PDF 和可编辑 PPTX 都从同一版画布导出。 |
| 面试面向具体公司及岗位 | 问题预测、公司及行业动向、带追问钩子的 STAR 案例、面试反问，均与投递岗位关联。 |

**首版开发默认值。** 下文给出可替换的实施选择，包括桌面 Web 优先、常见文件格式、定性匹配顺序、保存时机、接口约定和上传上限。产品要求以上表为准。开发无需等待供应商、数据库或模型选型才能按这些行为联调。

## 2. 入口、导航与两条用户路径

首页问“你想投哪个方向？”三张卡片分别显示计算机、互联网、金融。点卡片就地展开岗位列表。选好后，页面问“你这次想怎么开始？”两张任务卡分别进入首次制作和定向微调。已经有 JD 的用户可以直接粘贴或上传，识别后显示可改的方向及岗位。方向未定的新手可以先整理经历，稍后再比较岗位。

| 大类 | 首屏展开后的岗位示例 | 如何影响后续工作 |
|---|---|---|
| 计算机 | 开发、算法、数据、测试 | 例如算法岗优先检索评测设计和改进证据，追问指标口径；开发岗更关注承担的模块、交付状态和性能证据。 |
| 互联网 | 产品、运营、市场营销、KA 大客户 | 同一个 AI 项目，产品岗关注判断与验证，运营岗关注试用及反馈，KA 岗关注需求澄清、客户推进和实际合作阶段。 |
| 金融 | 行研、投研、投行、资管、风控等 | 行研看研究问题、分析方法和产出用途；风控看识别风险、评估与处理。具体以 JD 职责为准。 |

岗位允许搜索或填写原称，例如“AI 产品运营”。行业和业务属性由 JD 提取、用户可改。银行后端开发归“计算机／开发”，行业为银行。在一次对比中可加入不同大类的 JD，每份 JD 独立保存方向。切换目标只更新当前任务的选择，既有简历可从仓库找回。

**路径 A · 从经历开始。** 选方向或暂缓选择 → 添加材料或直接写一段实践 → 确认自己的角色与行动 → 选择方向或目标 JD → 勾选相关经历生成初稿 → 在具体条目旁补 R → 编辑并导出。没有实习的用户可用课程、校园实践、竞赛或研究经历完成这条路径。没有具体 JD 时，画布标注“按职业方向生成”。

**路径 B · 定向微调。** 导入已有简历并核对 → 加入一个或多个 JD → 查看匹配和差异 → 选一个目标并创建岗位版本 → 比较少量修改、逐条接受 → 局部手改或对话修改 → 导出。原简历本身就是经历来源，知识库里有额外材料时再引用，避免用户重新填一轮表。

**页面关系。** 左侧常驻四个工作台。顶部显示当前方向、目标岗位和当前简历名。经历台整理的是个人事实；打开某份岗位简历或面试包时，顶部切到它绑定的目标。退出后再打开同一简历，直接回到最新保存的画布。

| 页面 ID | 页面 | 主操作及下一步 |
|---|---|---|
| P01 | 方向与任务选择 | 选方向／导入 JD → 从材料开始或从简历开始 |
| P02 | 个人经历台 | 上传、手动录入、核对材料与事实 → 选经历制简历 |
| P03 | 岗位匹配分析台 | 导入多个 JD、核对识别、填写意向、并排比较 → 选岗做简历／准备面试 |
| P04 | 简历优化台 | 导入或生成、手动编辑、框选修改、补 R → 导出及归档 |
| P05 | 简历仓库 | 按标签找版本、继续编辑、下载已导出的文件 → 从投递版准备面试 |
| P06 | 面试打磨台 | 选公司、JD、投递版 → 准备问题、公司动向、案例和反问 |

## 3. 个人经历台 P02

**界面。** “材料”和“经历”是同一页面的两个视图。材料列表显示名称、类型、解析状态、关联经历。点击经历打开编辑区，左侧看角色、任务、行动、结果，右侧查看引用的页、幻灯片或原文摘录。缺少材料时，主按钮是“添加材料”，旁边可选“直接写一段经历”。

| 编号 | 触发与操作 | 系统行为和完成条件 |
|---|---|---|
| EXP-01 | 拖入论文、比赛 PPT、实习手册、旧简历或图片 | 默认支持 PDF、DOCX、PPTX、TXT、JPG、PNG，单文件 30 MB。支持多文件逐项处理。依次显示“上传中／解析中／可核对／失败”。失败项可单独重试或粘贴原文，其余文件照常可用。 |
| EXP-02 | 查看解析结果 | 同一文件可拆出多条经历，多份文件可关联同一经历。解析每项事实时保存文件、定位和原文摘录。PDF 用页码，PPTX 用幻灯片号，DOCX／TXT 用段落定位，图片用图号及摘录。扫描件先识别文字。 |
| EXP-03 | 确认经历卡 | 卡片按经历名、时间、个人角色、情境与任务、行动、结果整理。每项事实区分“材料明确／本人确认／待核实”。手动补充记录为本人确认；AI 推断、识别歧义及来源冲突列为待核实。 |
| EXP-04 | 合并或更正事实 | 展示冲突值和出处，例如“原型试点／已经上线”，由用户选定或改写。保留原始摘录和更正记录。团队成果与个人动作分别保存，避免把团队指标归到个人。 |
| EXP-05 | 在简历或面试中补充新事实 | 显示“同步到这条经历”选项。确认后写入经历库；对某一投递版本的措辞、字号、模块顺序保存在该简历。打开既有简历时，如相关事实更新，可查看差异并选择应用。 |

解析进度跟随材料，切换页面后可继续查看。文件为空、受密码保护或无法识别时给出具体原因，并保留手动录入入口。只有摘要但无法核实“谁做的”时，生成前追问“你具体负责哪一步？”。

## 4. 岗位匹配分析台 P03

**输入。** 一个任务支持一个或多个 JD，可粘贴文字，也可上传岗位截图／照片。多图可以属于同一岗位，上传后提供“合为一个 JD／分别建立 JD”。每个 JD 核对公司、岗位原称、职责、明确必需条件、加分条件和原文。公司名或必需条件识别不清时标记待确认。意向区记录用户偏好的方向和岗位，支持“优先／可接受／暂不考虑”；可留空。

| 编号 | 所在步骤 | 实现规则 |
|---|---|---|
| MAT-01 | 核对 JD | 图片识别结果可编辑并对照原图；粘贴文本也可修订。保存后生成 JD 修订号。重跑分析用选定的修订，旧分析仍能找到对应原文。 |
| MAT-02 | 建立证据对应 | 将去重后的每条岗位要求关联到具体事实及出处。结果取“直接支持／部分支持／待补信息／已知不满足”。只有明确相反的事实或用户明确表示不具备，才可判为已知不满足。 |
| MAT-03 | 多岗横向比较 | 每岗一列，同一行比较意向、明确必需项覆盖、优势及出处、主要差距和待补问题。点击“为什么”可展开 JD 原句及经历证据。单个 JD 使用同一结构。 |
| MAT-04 | 推荐顺序 | 默认先看用户意向，再看明确必需项中的已知缺口，最后看直接／部分支持的覆盖程度。并列显示同档和原因，保留加入顺序。每个推荐理由至少指出一条岗位条件及证据或明确缺口。 |
| MAT-05 | 选定目标 | “用这个岗位改简历／准备面试”带入 JD 修订、选中的证据和用户意向。修订 JD 或经历后，旧分析显示“资料有更新”，可重新比较。 |

**可实现的默认排序。** “优先”在前，“可接受”和未填写在中，“暂不考虑”在末。同一意向组内，有明确必需项的 JD 先按是否存在“已知不满足”分组，有明确缺口的后列；各组再按证据覆盖率降序，同档保留加入顺序。覆盖率为（直接支持项数＋0.5 × 部分支持项数）÷ 该 JD 去重后的明确必需项总数。若一个 JD 没写明确必需项，则在对应意向组末尾单列“条件待澄清”，继续按普通职责展示证据。没有证据时显示“资料不足”；待核实事实不能参与已支持项。前台展示“3 项有直接证据，1 项待补”一类可核查的描述。加分项单独展示。上述权重用于首版联调，界面不将其解释为录取概率。

**同一经历跨岗示例。** 已确认“整理试用反馈，跟进两处交互调整”，可直接支撑产品运营 JD 的“归纳用户反馈”；对于 KA JD 的“独立推进签约”，现有材料只能标“待补信息”。推荐语可提示补充是否接触客户，不能将上述工作改成“独立签约”。

## 5. 简历优化台 P04

### 5.1 起稿与定向微调

| 编号 | 从经历开始做简历 | 用现有简历适配岗位 |
|---|---|---|
| CV-01 输入 | 选择职业方向或目标 JD，勾选材料和经历；缺姓名、联系方式等投递信息时提示补充。 | 默认允许上传 PDF、DOCX、PPTX 或粘贴文本。导入时保留原文件，生成可编辑底稿，供用户核对文字、顺序与布局。 |
| CV-02 第一次打开 | 生成适合材料的栏目和经历条目，展示哪些贡献有证据、哪里还缺结果。在对应条目旁补信息。 | 左右查看原稿和可编辑底稿。可直接修正导入误差。原排版复杂或为扫描图片时标出需核对的位置；确认底稿后，复制为目标岗位版本。 |
| CV-03 AI 行为 | 从真实材料中选与目标有关的内容，用自然中文串起情境、任务、行动、结果。重点经历可有多条要点。 | 默认逐条建议，列出“原句／建议／岗位理由”，重排时显示从哪里移到哪里。可接受、拒绝或继续手改。保留个人角色、已做事项、指标口径、项目阶段。 |
| CV-04 输出 | 可编辑初稿，带有待补事项和来源入口。 | 已接受的修改进入岗位版本，拒绝的建议不进入正文。再次建议基于当前稿，保留未采纳记录供本轮查看。 |

**现有 skill 的使用。** 项目参考包位于同目录下的“参考资料/chinese-product-manager-cv.zip”。其中的写作规范、A4 版式、示意图和排版检查用于中文产品经理、AI 产品经理实习及校招的默认样式。首版对该场景应用自然 STAR、个人贡献概括、默认一页 A4 等规则。其他岗位先采用通用中文简历版式，加上本岗位的事实选择和结果追问。用户手动调整排版后的导出以画布为准。包内 PDF 脚本可作默认样式的比对样例，导出实现须支持编辑后的对象和 PPTX。

### 5.2 编辑器与局部修改

| 编号 | 交互 | 验收行为 |
|---|---|---|
| EDT-01 | 中央 A4 纵向画布，顶部格式工具和保存状态，右侧 AI 对话 | 单击选对象，双击改文字，可选择文字范围；工具栏支持字体、字号、粗体、对齐、行距。可移动和缩放文本框，拖动或用工具栏调整模块顺序。支持撤销／重做。 |
| EDT-02 | 框选文字、文本框或矩形区域 | 命中对象高亮，右栏显示“已选”及文本摘要。多对象可取消单项；空白选区提示重新选择。目标范围与指令一起送出。无选区时，用户可明确选择整页或整份简历。 |
| EDT-03 | 对话输入“把这条压成两行，保留试点范围” | 建议以选区所在的最新稿为底，预览文字或版式差异，并可定位原处。用户点“应用”后才改变画布。局部改写只更改指令涉及的字段，例如改文案不重设字号或坐标。 |
| EDT-04 | 连续手改或跨页返回 | 每次手改／应用建议更新画布，显示“保存中／已保存／保存失败”。开发默认停笔 800 毫秒触发保存，切页、请求 AI 或导出时立即提交待保存修改。失败保留本地草稿及重试入口。 |
| EDT-05 | AI 生成过程中用户继续编辑 | 建议携带当时的版本、目标对象和涉及的字段。目标字段没变可应用到最新版，保留同时进行的其他修改。目标字段已变时展示当前值与建议，让用户选择保留或基于当前值重算；对象已删则提示重新选区。 |
| EDT-06 | 撤销或预览 | 手改和已应用的 AI 修改均可撤销，一次 AI 操作作为一步。画布溢出、重叠或越过页边界时定位具体对象，允许用户调整位置、改文案或加页。建议、标注和选框属于编辑界面。 |

**指针操作的可替代入口。** 拖动排序有“上移／下移”，选中文本框可用方向键微调，撤销与重做提供按钮及常用快捷键。自动保存不抢焦点；选区追问和 AI 回答在右栏完成，保留画布位置。

### 5.3 STAR 结果三级追问

**触发。** 选中的核心经历缺少结果、成果归属含混，或用户主动点“补结果”。先查本人的材料和已确认事实，找到结果则展示候选原文供使用。仍缺时，按岗位及具体行动检索常见成果类型，生成 2–4 个相关选项。无适配条目时用交付、试用、采纳等通用类型。常见结果和示例数字只用于设计问题。一次只在当前条目旁展开一级，可返回上一步、换类型、手动填写或“稍后补”。

| 第一级 · 本人情况 | 第二级 · 这项工作产生过什么 | 第三级 · 最少要补什么 | 写入条件 |
|---|---|---|---|
| “我有量化结果” | 按任务给选项，如召回率、准确率、使用率、节省工时、交易额 | 数值、单位及影响含义的口径。如召回率需区分评测范围；“提升”需提供基线或改为最终值。 | 先生成结果短句，用户确认归属和表述后应用；范围或单位含混时继续询问。 |
| “暂无具体量化结果” | “被团队采纳”“有人试用”“完成交付／试点”等 | 选择采纳时问“谁将它用于什么？”；如知道，再填部门数、人数或范围。选择交付时问“交付了什么、到哪一步？” | 有范围用范围，有真实落地状态用状态。被体验、被采用、正式上线分别记录。 |
| “上述都没有” | 在前两条路径找不到合适结果后，单独显示“主管或负责人明确认可过这项工作吗？” | “有／没有／不确定”。选“有”再填写对方认可了哪项工作；选“没有／不确定”可稍后补。 | 只有本人确认才使用认可反馈。待补条目保留行动；导出前提示结果仍待补，可继续补写或按当前事实导出。 |

**成文示例，数字仅用于验收。** 用户选择“召回率”，填写“96%”，说明是“在离线测试集上的最终值”，并确认是团队指标、本人负责评测。可写“负责离线评测，团队方案在该测试集上的召回率为 96%”。若用户选择“被采纳”，确认“两个部门将这份清单用于每周复盘”，可写“整理复盘清单，获两个部门采用”。输入框留空时，示例数字不得写入正文。

已确认的结果存到当前经历条目，生成自然句子，标记来源，并提供同步到经历库的选择。再次打开同一条目回到已填写的位置。撤销简历改写时可以恢复原文，已单独确认存入经历库的事实仍可查阅。

## 6. 导出、归档与投递版本 P04／P05

| 编号 | 用户操作 | 开发行为与验收 |
|---|---|---|
| OUT-01 | 点击“导出”，选择 PDF 或可编辑 PPTX | 先提交输入法正在编辑的文字及未保存操作，再固定当前修订。预览显示文件名、页数、格式与版式提示。保存失败时保留画布并提示重试。用户导出时可以选择或补充版本标签。 |
| OUT-02 | 导出 PDF | 从该修订的页面尺寸、对象坐标、富文本和样式渲染。正文可选中复制，中文、英文、数字与加粗正常显示；页数、换行、顺序、对象位置与预览一致。内部标注、待补提示、选框均不出现在文件中。 |
| OUT-03 | 导出 PPTX | 每页画布对应一张同尺寸纵向幻灯片。标题、正文、日期和主要文本框是可编辑对象，主要对象可移动。照片保留为图片；字号、坐标、段落样式来自同一修订。测试基准使用安装约定字体的 PowerPoint，对照同一页预览。 |
| OUT-04 | 文件生成期间又编辑 | 下载和归档绑定发起时的修订号。生成失败显示原因并可重试相同修订；成功后条目才有可下载文件。相同用户、修订和格式重复提交或重试，复用归档结果。 |
| LIB-01 | 打开简历仓库 | 展示版本名、对应公司和岗位、标签、导出时间、可用格式。标签默认建议“产品／运营／KA／营销”等，允许用户自定义和多选。可按标签、公司或岗位找到版本。 |
| LIB-02 | 在仓库继续编辑或准备面试 | 区分“继续编辑工作稿”和“从这份导出版本另存”。后者从不可变快照派生工作稿，旧文件可继续下载。面试入口携带用户选中的确切修订；同一修订导出的 PDF、PPTX 挂在同一条目下。 |

**保存状态。** 自动保存产生工作稿修订；导出成功产生仓库中的投递版本。重新打开工作稿恢复最新修订，打开历史导出预览还原当时修订。在当前会话编辑但断网时提示“本机有待保存修改”，恢复网络后按版本检查保存；多人或多标签页对同一字段有冲突时让用户选择。

## 7. 面试打磨台 P06

**入口条件。** 选择公司和 JD，从仓库挑选实际投递的简历，或使用当前已保存的工作稿。页头固定展示公司、岗位、JD 修订及简历版本。尚无简历时，可先凭 JD 准备岗位问题和反问；涉及个人经历的内容在用户选择经历或简历后生成。界面标明材料范围，用户可以回到对应条目核实。

| 编号 | 分区 | 输入、输出与交互 |
|---|---|---|
| INT-01 | 面试问题 | 依据 JD 要求、简历重点和事实空缺生成问题卡。每卡显示“可能怎么问、为什么可能问、可用哪段经历回答、可能的追问”。可点开所引 JD 原句／简历条目；标明“预测问题”。 |
| INT-02 | 公司及行业动向 | 以公司名、业务线和岗位为条件检索公开资料。动向卡展示事件、发生或发布日期、来源标题与链接、与岗位的关联。首先使用公司公告、官网等可核查来源；查不到可靠来源时显示“暂无可核实动向”，支持补充来源。区分公开事实与对面试的推测。 |
| INT-03 | Golden Case | 先推荐适合该岗位的经历及理由。用户选一条后生成 S 情境、T 本人任务、A 本人动作与取舍、R 已证实结果，以及一段可口述的回答。结果不足时复用第 5.3 节的追问。各段可单独修改、保存。 |
| INT-04 | 追问钩子 | 每个重点案例提供一句来自真实细节、可自然放入回答的钩子，附最可能的追问和回答依据。选择保留后嵌入口述稿，缺少支撑时提示补充细节或移除。 |
| INT-05 | 面试反问 | 每项给出“可以怎样问、适合向谁问、希望了解什么”，并说明与该岗位职责或公开背景的联系。对尚未核实的公司动态使用开放式问法。 |

**示例。** 面向 AI 产品运营，经历写明“试用反馈集中在两个流程，先改其中一个”。钩子可以是“第一次迭代时，我只推动团队改了其中一个流程”。对应追问“为什么选这个？”回答要能回到用户确认过的优先级依据。材料里只有改动结果时，询问当时的判断，等待用户补充后再写。

**跨版本一致性。** 面试包固定本次选中的 JD 和投递稿修订。新版经历与旧投递稿数值不一致时并排显示原表述和更正依据，让用户决定如何说明变化；回答中不能把后来才上线的结果描述成投递时已经上线。切换岗位时允许复用同一条经历，重新选择侧重点，分别保存案例稿。

## 8. 数据对象与版本关系

下表给前后端统一数据含义。ID、状态、来源引用和版本检查属于接口合约，存储方式由实现团队选择。

| 对象 | 关键字段 | 关系或约束 |
|---|---|---|
| 求职任务 | id、ownerId、大类、岗位原称、行业属性、制作模式、意向列表、当前目标 | 同一用户可创建多个目标，经历库按用户共用。 |
| 原始材料／引用 | materialId、ownerId、原件位置、格式、解析状态；sourceRef 含 materialId、页／段／幻灯片号、摘录 | 一个材料可服务多条经历；本人陈述记录确认时间与原话。 |
| 经历／事实 | experienceId、factId、角色、事实类型、值、单位、范围、个人／团队归属、证据状态、sourceRefs、factRevision | 支持一事实多来源。缺事实与事实为零是不同值。更正后可以查到使用过的旧事实。 |
| JD／岗位要求 | jdId、jdRevision、公司、岗位、大类、原文、requirements | 每条要求有 requirementId、原句、必需／加分／普通、来源。保留修订以重现对比。 |
| 匹配结果 | matchId、意向快照、JD 修订列表、经历事实修订列表、逐项状态、理由、factRefs | 同次对比使用同一批事实与意向。匹配结果不足以成为新的个人事实。 |
| 简历工作稿／修订 | resumeId、parentRevisionId、headRevision、目标 JD、起稿模式、画布、已用 factRefs | 手改、AI 修改与撤销均从当前稿形成新状态。角色、正文与样式分别更新。 |
| AI 建议／批注 | proposalId、resumeId、baseRevision、target、operations、引用、应用状态 | 批注记住选区。应用操作包含对象 ID、字段及原值检查；重复应用只生效一次。 |
| 结果追问 | experienceId、对应简历条目、卡片类型、当前层级、用户输入、实际值与口径、状态 | 待补／草稿／本人已确认，可恢复。确认的结果才可应用到简历。 |
| 导出／仓库条目 | exportId、resumeId、revision、format、状态、文件、时间；条目含岗位、公司、tags | 条目以工作稿和修订标识，一个条目可挂两种格式。导出文件与修订绑定。 |
| 面试包 | packId、jdId 及修订、resumeId 及修订（可空）、经历引用、问题卡、案例、钩子、反问、来源 | 保存用户修改及来源日期。切换公司或简历版本时显式选择是否生成新的面试包。 |

**画布合同。** 采用统一页面单位 pt。默认 A4 纵向，页面、模块和对象均有稳定 ID；每个对象至少保存类型、所属页、位置及尺寸、叠放顺序、富文本分段和段落样式。手工换行与自动折行分别处理。简历条目通过对象关联经历事实；文字位置采用明确的字符索引约定，前后端统一以 UTF-16 偏移计数。文本选区同时保存原选句和邻近上下文，位置发生变化时先重新定位。定位不唯一则提示重新选择。

| 状态对象 | 合法主流程 | 失败及恢复 |
|---|---|---|
| 材料／JD 识别 | 已接收 → 处理中 → 可核对 → 已采用 | 解析失败可重试或手动输入。乱码或低置信识别进入核对。 |
| 编辑器 | 已保存 → 有修改 → 保存中 → 已保存 | 保存失败留住草稿；版本冲突拉取最新稿并合并无冲突字段，其余由用户选择。 |
| AI 修改建议 | 生成中 → 可预览 → 已应用／已放弃 | 失败可重试；目标变动转“需核对”，对象删除转“需重选”。 |
| 导出 | 排队 → 渲染中 → 已完成 | 失败保留错误和原修订供重试；按成功的文件更新仓库。 |
| 面试生成 | 选择资料 → 生成中 → 可编辑 → 已保存 | 公司资料检索或某一分区失败时可单独重试，已编辑的分区仍可使用。 |

## 9. 前后端与 AI 联调约定

以下是建议的 HTTP 合约。技术栈可换，但需要保留修订检查、来源、选区、错误状态以及可重试语义。所有读取、下载、修改都校验资料归属。文件解析、匹配、AI 生成和导出返回 jobId，前端轮询任务状态或接收等价推送。AI 只生成候选结果，是否写入由相应页面的保存或应用操作决定。

| 操作 | 请求要点 | 返回与错误 |
|---|---|---|
| POST /materials；GET /jobs/{id} | 文件、材料用途；查询异步任务 | materialId、jobId；任务返回 status、resultRef、errorCode、retryable。类型不支持或超限时给出允许值。 |
| GET /experiences；PATCH /experiences/{id} | 查看卡片；提交已确认字段、来源和基准修订 | 事实状态及新修订；冲突返回当前值，保留用户输入。 |
| POST /jds；PATCH /jds/{id} | 原文或图片 materialIds、一张或多张、用户核对字段 | jdId、解析状态、requirements、jdRevision。 |
| POST /matches | 选中 JD 修订、经历事实快照、意向 | jobId，完成后返回分项匹配、证据和排序理由。 |
| POST /resumes；GET /resumes/{id} | 制作模式、方向、可选 JD、选中的经历／原稿／父修订 | resumeId、headRevision、可编辑画布。原稿解析或初稿生成可异步。 |
| PATCH /resumes/{id}/canvas | baseRevision、操作列表、每个涉及字段的预期值、requestId | 返回新 revision。可安全合并时基于最新版写入，有冲突返回 409、当前修订及冲突字段。 |
| POST /resumes/{id}/proposals；POST /proposals/{id}/apply | 当前修订、指令、选区、事实引用；应用时携带当前修订 | 生成后返回预览差异及可应用操作。接受后返回最新画布修订；过期选区需重新定位。 |
| POST /result-prompts；PATCH /result-prompts/{id} | 经历条目、岗位、动作、已知结果；提交选择、值及范围 | 返回当前层、候选项、已填草稿、预览句。提交确认后返回事实候选及可应用改写。 |
| POST /exports；GET /library | 已保存的 resumeId、revision、format、所选标签；查询标签／岗位／公司 | jobId，完成后返回归档条目及私有下载地址；相同修订同格式可重试复用。 |
| POST /interview-packs；PATCH /interview-packs/{id} | 公司、JD 修订、投递稿修订或已选经历、目标分区；保存分区修改 | packId、分区状态、问题和案例、资料来源或明确的空状态。 |

**最小选区示例。** 用户选中“负责用户反馈”六个字时，模型收到目标文本和允许改写的范围，应用时服务端再核对。以下为预览补丁中的一项，字符区间采用左闭右开。

```json
{
  "baseRevision": 12,
  "objectId": "text-17",
  "field": "text",
  "range": { "start": 0, "end": 6 },
  "expectedText": "负责用户反馈",
  "replacement": "整理试用反馈",
  "factRefs": ["fact-07@2"]
}
```

**AI 输出的四项检查。** 匹配结论引用 requirementId 和事实 ID 或明确标缺口；简历改写引用可用事实、说明变动并限制在授权选区；结果选项可包含示例但示例永不充当填写值；面试案例中的个人事实和公司动向分别引用经历或公开来源。后端先校验输出结构、引用归属、数字来源和目标范围。结构无效或引用不存在时停止应用，允许重试。上传文档与 JD 中的文字只作为待分析材料。

**通用错误。** 格式错误、文件过大、原件受保护、识别失败、资料不足、生成失败、保存冲突、选区失效、导出失败分别返回可展示原因和下一步。越权访问拒绝返回内容。每次写入带唯一请求标识，重试同一请求不重复插入条目或修改正文。

## 10. 页面细节与首批 AI 配置

**页面组件与操作顺序。** 前端可据下表拆组件和联调空态。任务进行中显示正在处理的对象；用户切换窗口或页面后仍能回到同一任务。AI 改字、挪动模块、写入知识库和导出是四种不同操作，按钮文案写出实际动作。

| 页面 | 默认布局 | 持续可见的操作或状态 |
|---|---|---|
| 经历台 | 左边材料列表，中间经历卡，点出处展开右侧原文。新手卡片按“做了什么／哪一步由你负责／最终交给谁”逐步提问。 | 添加材料、直接写经历、核对事实、回到原文 |
| 匹配台 | 上方是 JD 和意向选择，中部按岗位分列比较，展开要求查看证据。较多岗位时横向滚动并固定行标题。 | 新增 JD、修正识别结果、选择作为本次目标 |
| 优化台 | 中央画布与右侧对话并列；选区后右栏直接带上对象摘要。结果追问卡在当前条目旁触发，在右栏逐级展开。 | 当前简历名、保存状态、撤销／重做、选中范围、预览、导出 |
| 仓库 | 标签筛选后显示包含公司、岗位和时间的版本列表，同一版本显示可下载的格式。 | 下载投递文件、继续编辑、从该版本准备面试 |
| 面试台 | 公司／JD／投递版固定在顶部，下方切换问题预测、公司动向、Golden Case、反问。 | 查看依据、局部改写、保存当前案例、回到投递版 |

**结果候选的首批配置。** 检索至少使用“目标岗位＋本条实际动作”，按材料包含的动词和工作对象选择问题。下列是开发样例，可维护为可版本化的配置表（岗位、动作、结果类型、单位、追问文案），也可接入检索服务。常见结果类型命中后仍要经过本人填写与确认。

| 岗位与经历动作 | 第一级选“有量化结果”时 | 第一级选“暂无具体量化结果”时 |
|---|---|---|
| 算法 · 做离线评测 | 最终召回率／准确率、比较基线、测试集范围 | 完成评测报告、发现问题被用于下一次迭代 |
| 开发 · 优化接口 | 耗时、吞吐、错误率，追问测试环境和前后值 | 完成联调、通过验收、进入试点 |
| 产品／运营 · 跟进用户试用 | 使用率、试用人数、反馈处理数，追问分母或周期 | 哪些团队试用、哪条建议进入迭代 |
| 市场 · 执行活动 | 触达人数、报名数、转化，追问渠道与时间 | 物料在哪里使用、活动是否实际执行 |
| KA · 跟进客户需求 | 接触客户数、进入试点数、已成交金额，确认阶段和归属 | 谁确认需求、是否完成演示或进入试用 |
| 金融研究 · 编写研究材料 | 覆盖标的数量、完成的调研范围 | 成果用于哪次讨论、哪部分被研究团队采用 |

**读写补充。** P01 保存或更新求职任务及偏好，P02 支持创建纯文本经历、替换确认字段及关联材料，P05 支持读取某一指定修订和更新标签，P06 支持读取、保存或重试指定分区。建议分别使用 /tasks、/experiences、/resumes/{id}/revisions/{revision}、/library/{id}、/interview-packs/{id} 资源，读用 GET，创建用 POST，更新用 PATCH。查询后台作业结束后，按 resultRef 获取可编辑结果或错误详情。

## 11. 验收用例

测试准备一份虚构候选人资料，包含一份可正常抽取的旧简历、一份扫描版 PDF、两页竞赛 PPT、一段实习手记、两个不同方向的 JD（其中一个用截图）和一个带 3 个可移动文本框的基准画布。预先给测试数据标出个人与团队归属、原文位置、已知数值和确实缺失的事实。以下为功能验收场景，均在正常用户页面执行。

| 用例 | 操作 | 通过标准 |
|---|---|---|
| T01 入口与路径 | 分别从三大类选择岗位；用“先整理经历”进入后再选方向 | 一级只有计算机、互联网、金融。新手与已有简历两条路径都能到达同一编辑器，生成或微调策略不同。 |
| T02 新手从零完成 | 仅上传竞赛 PPT 和校园实践，确认自己的动作，无实习、无具体 JD | 能生成方向明确的简历，经历来自用户材料，无虚构实习；可手改、补 R 并导出。 |
| T03 事实冲突 | 两份材料分别写“完成试点”“正式上线”，同一数据另有个人／团队两种说法 | 提示核对并能跳到原句。核对前，冲突结果不进入正文；确认后可查到采用值和出处。 |
| T04 多 JD 比较 | 上传运营岗截图、粘贴 KA 岗文字，纠正一处识别错误，设置岗位偏好 | 两岗基于同一批经历横比；岗位要求各自独立。推荐给出偏好、证据和缺口，缺少签约证据标“待补信息”。修改意向重算可改变推荐顺序。 |
| T05 微调真实边界 | 将 AI 产品经历适配运营或 KA；只接受重排和一条措辞调整 | 个人职责、时间、数据、项目阶段与原稿一致。拒绝的改写没有进入新稿，原稿仍可打开。 |
| T06 量化 R | 选择召回率，先留空，再填 96%、离线测试集、团队结果并确认 | 留空时没有示例值进入正文；确认后的句子保留指标范围与归属。已填内容再次打开可恢复。 |
| T07 暂无量化 R | 选“暂无具体量化结果”后选“有人试用”，填“两个部门试用”；返回改成“一个部门试用” | 预览随之更新，保存为“一个部门试用”；不能升级成“全面采用”或“已上线”。 |
| T08 无 R 的兜底 | 无实际采用或数据，选负责人反馈，分别走“有、没有、不确定” | “有”且补充真实反馈后可确认应用；其余保留待补状态，可按现有事实导出，正文无“获认可”字样。 |
| T09 手改三处再改第四处 | 手改姓名字号、一个项目标题、项目模块位置，再框选另一句要求 AI 压成两行 | 三处手改与局部改写同时存在；撤销一次只恢复选句，重做后刷新仍能恢复全部。两种导出都包含这四处最终状态。 |
| T10 并行修改 | AI 处理中先改同框位置，再改选中文字；另测删除目标框 | 只移动时可以应用文案并保留位置。选句被改时提供保留／重算选项，删除目标后提示重选。另一标签页持有旧稿也不能覆盖新稿。 |
| T11 导出与可编辑性 | 对同一修订导出两种格式，导出发起后继续手改，再重试一次相同导出 | 仓库仍是对应修订的一条记录，带两种格式。PDF 可复制正文；PPTX 逐字可改、文本框可拖动。两者页数、对象次序、换行与该修订预览相符，主要对象边界偏差默认容差 1 pt（基准字体环境）。 |
| T12 选对面试版本 | 给同一岗位先后制作两稿，在仓库选择第一稿准备面试 | 页头、预测依据和案例均引用第一稿；追问能追溯真实细节。动向卡有来源和日期，检索失败显空态。反问说明与岗位的关系。 |
| T13 故障与恢复 | 上传受保护 PDF、故意中断一次保存和一次导出 | 分别可手动输入、恢复草稿、重试导出。失败导出没有可下载文件，重试成功才进入仓库。 |
| T14 数据归属 | 用另一测试用户打开经历原件、简历修订、面试包或下载链接 | 服务端拒绝授权范围外的访问。日志记录任务 ID 和错误类型，通用运行日志不写入简历正文、联系方式或原始附件。 |

**体验验收默认值。** 以桌面 1366 × 768 及以上、正常网络、两页简历和常见中文字体作为首轮验收环境。选中对象、切换追问卡和拖动操作本地响应目标为 100 毫秒内；首次点击 AI、识别或导出后 1 秒内出现处理中状态。耗时任务可离开页面再回来，失败后能在原位置重试。持续打字不跳光标，局部修改后仍能看见原选区。

## 12. 开发顺序与交付边界

| 开发批次 | 可独立演示的交付 | 依赖与放行条件 |
|---|---|---|
| 1 · 走通最高风险的编辑及导出 | 用固定结构化样例打开 A4 画布，手改三处，应用第四处局部补丁，保存、重开并导出两种格式 | 先约定画布、修订和导出快照；通过 T09–T11 的核心路径。 |
| 2 · 经历和岗位 | 完成入口、材料解析与人工核对、个人经历、JD 核对、意向及横向比较 | 使用第一批的事实引用和版本合同；通过 T01、T03、T04。 |
| 3 · 打通两种简历制作路径 | 新手初稿、已有简历的底稿核对与微调、三级 R 卡、自动归档、标签和历史版本 | 连接前两批。用真实解析与生成替换样例；通过 T02、T05–T11，抽查 PDF 与可编辑 PPTX。 |
| 4 · 面试与整体验收 | 从仓库选择投递版，生成并编辑问题、案例、钩子、反问及带来源的公司动向 | 通过 T12–T14，完整走通两条用户路径，再用相同资料换一个岗位复测。 |

首版交付的判断依据是用户能以真实材料完成上述两条路径，能解释一项岗位推荐的依据，能从当前画布导出可投递、可继续编辑的版本，并能针对该投递稿讲清一个有事实支撑的案例。
